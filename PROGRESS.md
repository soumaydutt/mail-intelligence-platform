### Engine 2 MX-target address policy follow-up (2026-10-16)

- The DNS engine now checks each distinct MX target for an A/AAAA address in ascending preference order. A usable target yields positive domain routing evidence; an earlier transient target failure followed by a usable backup yields `MX_TARGET_PARTIAL`. If no target has an address, `MX_TARGET_NO_ADDRESS` records negative routing evidence; temporary failures yield retryable `MX_TARGET_TEMPORARY_FAILURE`, while an exhausted query budget yields retryable `DNS_QUERY_BUDGET_EXCEEDED`. Malformed answers and exchanger CNAMEs are uncertain under `MX_TARGET_UNCERTAIN`, following RFC 5321 §5.1. This never claims SMTP acceptance or mailbox existence. The legacy `mxRecordFound=true` still means only that an ordinary MX was observed, even if target routing failed.
- Before the fix, focused regressions failed twice: an MX with SERVFAIL at its target returned `MAIL_ROUTE` instead of `UNKNOWN`, and an MX with no target address returned `MAIL_ROUTE` instead of `NO_MAIL_ROUTE`. A later red/green test caught a mixed A NOERROR/NODATA then AAAA NXDOMAIN response falsely returning `NO_MAIL_ROUTE`; mixed A SERVFAIL then AAAA NXDOMAIN now remains retryable unknown.
