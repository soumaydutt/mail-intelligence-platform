# Phase 11 browser API inventory

Source: `src/main/java/com/aash/mailguard/{controller,imports,delivery,exception,ratelimit}` at baseline `5cd35c1b0a5c84de6fc5d6e1691c62014c6dda10`. All browser traffic uses the same-origin Vite development proxy or a trusted same-origin production reverse proxy; **never** put the shared administrative key in a URL. A single key grants access to all administrative records, not per-user ownership. No CORS wildcard or new backend route is added.

**Errors and retries:** API/controller-advice JSON has `{timestamp,status,message,path}` with sanitized messages and redacted dynamic paths. A configured limiter can return `401` before handler parsing, `429` with positive `Retry-After` and `RateLimit-*` headers, or `503` for authenticated routes when shared Valkey admission fails. Queue/upload admission can also return `429` with `Retry-After: 1`. Public requests have bounded local outage fallback. Do not automatically retry an administrative mutation or an invalid credential; parse `Retry-After` as seconds or HTTP date and cap the displayed delay. Backend `401` means failed authentication, `403` means forbidden if ever returned, `413` oversized request, `429` throttled, `503` shared admission/backend outage. Connection errors have no HTTP status. The client uses a typed schema and fixed safe error messages rather than rendering arbitrary response HTML.

**Unsupported workflows:** There is no authenticated validation-history read, job list, import list, global delivery-event listing, aggregate activity metrics, per-user authentication or tenant ownership. The UI shows session-only validation and known job/import identifiers, bounded exact-email delivery lookups, and the real keyset suppression list. A new history/list API would require approved retention/ownership policy first; none is introduced in Phase 11.
